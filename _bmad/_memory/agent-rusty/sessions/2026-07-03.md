## Session — frontend IA audit: project landing page + Release Health placement (extends #166)

**What happened:** Abian asked whether Rustrak's `/projects/[id]` redirect-to-issues and the "Release Health" button-on-issue-page pattern match how Sentry's frontend actually organizes this. Investigated `~/.rusty/sentry-repo/static/app/` (SHA a32a33a) directly — router, projectDetail view, explore/releases views — instead of relying on docs.sentry.io. No filters/search work touched, per explicit owner instruction (deferred to later).

**Key findings:**
- `/projects/:projectId/` in real Sentry → `sentry/views/projectDetail` (routes.tsx#L1240-L1243), a dashboard, never a redirect. Confirms #166 priority #1/#7 against actual router source, not just docs.
- Issue stream in real Sentry lives at org level (`/organizations/:orgId/issues/`, routes.tsx#L2578), not nested under a project route — deeper IA difference than #166 called out.
- "Release Health" has **no standalone page or button anywhere** in Sentry's frontend (grepped all of `static/app/views/` for the term). It's data woven into 3 places only: project dashboard score cards (`projectScoreCards/projectStabilityScoreCard.tsx`), the releases list (`explore/releases/list`, with a `ReleaseHealthCTA` prompting to add it), and a release's detail page default "Overview" tab (no separate "Health" tab — tabs are Overview/Commits/Files Changed/Builds).
- Rustrak's `release-health-sheet.tsx` (triggered from `project-header.tsx` on the Issues page) puts this data on a page Sentry doesn't, as a destination Sentry doesn't have.
- Rustrak has zero "Releases" concept in the UI at all — no list, no detail page.
- Cross-checked against Abian's own live Sentry tenant reference (`marketec360.sentry.io/explore/releases/`) — matches the source-derived structure.
- **De-risking finds for implementation**: Rustrak already has more than it looked like — `GET /api/projects/{id}/sessions/stats` already returns one row per (release, environment) with crash_free_sessions_rate/crash_free_users_rate/total/crashed etc. (`models/session.rs:107-117`, `services/session.rs` `query_release_health`); `issue.first_release` already exists (`models/issue.rs:80`) enabling a "new issues in this release" feature with zero new backend capability; `recharts@3.9.1` already a frontend dependency. The only real backend gap for chart trends is that `session_counts` has a `bucket` column at storage level but `release_health()` collapses it with `SUM()` — no time-bucketed query exists yet.

**Rustrak gaps confirmed:** Both written to BOND.md this session — "Project landing page: redirect-to-issues vs dashboard" and "'Release Health' has no dedicated page/button anywhere in Sentry" (extends #166).

**Decision:** Abian approved all 3 phases (Overview landing page, Releases list/detail page replacing the Sheet, time-bucketed sessions endpoint for trend charts) and asked to move straight to implementation — backend via `/tdd`, frontend without tests (no frontend test infra exists yet in this repo). This pushes past Rusty's boundary (investigate/recommend only, never modify source) — implementation continues as regular Claude Code work, not as Rusty. Session closes here.

**Follow-up:** None for Rusty specifically — next Rusty session should check whether the implementation changed anything worth a compat gap update (e.g. if new session-stats endpoint shapes diverge from what Sentry's equivalent API returns, that'd be worth an [AU] pass).
