## Session — Verifying transaction item fix in ingest.rs

**What happened:** Abian deployed v0.5.0 with session tracking. All new issues showing "Unknown" title. Root cause: the review-feedback commit (4ee170c) for PR #117 changed `if event_item.is_none()` to `if matches!(t, "event" | "transaction" | "security") && event_item.is_none()` — transactions started being captured as event_item and sent to the error digest pipeline, where they fall back to "Unknown" (no exception/logentry).

**Key findings:**
- Relay `ErrorsProcessor.prepare_envelope()` has an explicit `has_transaction` guard: if the envelope contains a `Transaction` item, `ErrorsProcessor` returns `None` (skips error processing entirely). Permalink: `relay-server/src/processing/errors/mod.rs:80–88` SHA 4222d43e.
- Transactions go to `TransactionProcessor` (relay-server/src/processing/transactions/mod.rs:70) — separate pipeline.
- `requires_event() == true` for Transaction in Relay is about envelope-level event_id requirement, NOT about error processing. Rustrak's `item_requires_event()` correctly returns true for "transaction" for this reason.
- Fix: `matches!(t, "event" | "transaction" | "security")` → `t == "event"`. Correct and aligned with Relay.
- Side effect: `security` items (CSP reports) now excluded too. They were never processed correctly anyway — they created "Unknown" issues. Acceptable for now.

**Rustrak gaps confirmed:** none new — this was a regression from a code review change, not a protocol gap.

**BOND.md update:** "Transaction/performance items — silently ignored" was listed as Known Missing. Still true. The fix restores that behavior after a regression.

**Follow-up:** 
- `security` item handling could be implemented as a future feature (CSP → event conversion, like Relay does).
- BOND.md Known Missing: "Transaction/performance items — silently ignored" status unchanged.
