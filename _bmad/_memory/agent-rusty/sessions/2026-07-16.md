## Session — real-SDK validation of #180 (AI Agent Monitoring) surfaces a wire-format gap; investigated Spans Protocol v2

**What happened:** Abian had me (via the parent session, before invoking `/agent-rusty` directly) build a real integration test for #180 using `@sentry/node@10.65.0`'s `vercelAIIntegration()` + the real `ai` (Vercel AI SDK) package's `generateText()` with a tool-calling multi-step loop, `MockLanguageModelV3` standing in for the LLM (no network needed). Captured the actual envelope bytes off the wire (local HTTP echo server as the DSN target, had to hand-roll chunked-transfer-encoding parsing since the SDK uses `Transfer-Encoding: chunked`). Result: the real SDK does not send the legacy standalone-span format #180 was built and tested against — it sends **Spans Protocol v2** (`application/vnd.sentry.items.span.v2+json`), which Rustrak's ingest pipeline doesn't recognize at all. Reproduced the resulting failure against a live `docker-compose.dev.yml` Rustrak server: `Failed to store standalone span: Validation("span missing span_id")`. Invoked as Rusty to investigate the v2 protocol in depth against relay-repo source and produce an implementation spec.

**Key findings:**
- Wire format: `{"type":"span"}` item header + `content_type: application/vnd.sentry.items.span.v2+json` → a BATCHED container `{"version":2,"items":[...]}`, not one-span-per-item. Confirmed: [relay-server/src/envelope/container.rs#L380-L386](https://github.com/getsentry/relay/blob/f42b1c8a15bba8cb96d1dfd3bd2b3158c7817c5f/relay-server/src/envelope/container.rs#L380).
- v2 `SpanV2` struct has no top-level `op` (lives in `attributes["sentry.op"]`), `name` instead of `description`, `end_timestamp` instead of `timestamp`. Attributes are typed `{"value":..., "type":"string"|"integer"|"double"|"boolean"|"array"}` pairs, not a flat object. [relay-event-schema/src/protocol/span_v2/mod.rs#L13-L56](https://github.com/getsentry/relay/blob/f42b1c8a15bba8cb96d1dfd3bd2b3158c7817c5f/relay-event-schema/src/protocol/span_v2/mod.rs#L13), [attributes.rs#L14-L176](https://github.com/getsentry/relay/blob/f42b1c8a15bba8cb96d1dfd3bd2b3158c7817c5f/relay-event-schema/src/protocol/attributes.rs#L14).
- For this SDK/config, the trace ROOT span goes out as a legacy `"transaction"` item (`contexts.trace`, with client-side accumulated token/cost totals), while children go via the v2 container — `spans: []` in the transaction event is always empty. `is_segment: true` on a v2 entry is a legitimate standalone root too (per Relay's own basic test fixture), not dependent on a transaction wrapper.
- Relay still supports the legacy format (`legacy_spans` module, routes bare non-container `{"type":"span"}` items — [legacy_spans/mod.rs#L99](https://github.com/getsentry/relay/blob/f42b1c8a15bba8cb96d1dfd3bd2b3158c7817c5f/relay-server/src/processing/legacy_spans/mod.rs#L99)) but modern SDKs no longer emit it for OTel-instrumented spans (AI Agent Monitoring included) — corrects the 2026-07-14 BOND.md row's framing, which conflated server-side feature-flag routing with what SDKs actually put on the wire.
- v2's AI normalization (`relay-event-normalization/src/eap/ai.rs`) reuses Rustrak's already-ported `infer_operation_type` unchanged (same function, `crate::span::ai::infer_ai_operation_type`) — no duplication needed there. It adds two fields Rustrak doesn't have (`tokens_per_second`, `context_utilization`/`window_size` — the latter needs a model-context-size table Rustrak doesn't maintain; recommended skipping, no widget needs it).
- **Independent bug found**: Rustrak's `services/gen_ai.rs` cache/reasoning token cost lookup uses LEGACY key names (`gen_ai.usage.input_tokens.cached` etc. — correct for legacy spans, verified against `span.rs#L496-L515`) but real v2-sourced spans use different key names (`gen_ai.usage.cache_read.input_tokens` etc., verified via literal test fixtures in `eap/ai.rs#L297`). No bridge exists between the two conventions anywhere in Relay. Prompt-cache/reasoning costs silently compute as $0 today for any v2 span.

**Rustrak gaps confirmed:**
- No Spans Protocol v2 ingestion at all → #180 (AI Agent Monitoring) receives zero data from real Sentry SDKs as shipped. Full spec written: `_bmad-output/implementation-artifacts/story-span-v2-protocol.md`.
- Cache/reasoning token pricing keys wrong for v2-format spans (bug, not a missing-feature gap) — folded into the same story as Task 3.
