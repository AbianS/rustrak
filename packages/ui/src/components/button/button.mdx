<P><code>selected</code> writes <code>aria-pressed</code> on every variant, so it is a toggle to anything that reads the page. Only <code>secondary</code> and <code>ghost</code> draw the pressed treatment: a primary is already the screen's main action, so there is nothing left for it to look switched on against. Reach for it on a control that is genuinely two-state, and not on a primary.</P>

<Section
  n="08"
  title="What it guarantees"
  intro="Every line is asserted by a story in the sidebar, not by this page."
>

<Guarantees>
  <Guarantee>A button with no label requires <code>aria-label</code>, and the type enforces it: <code>{'<Button icon={X} />'}</code> with no name does not compile.</Guarantee>
  <Guarantee story="SelectedIsAnnounced"><code>selected</code> publishes <code>aria-pressed</code> in both directions, so a filter that is off still announces itself as a toggle.</Guarantee>
  <Guarantee story="DoesNotFireWhileLoading"><code>loading</code> sets <code>aria-busy</code>, swaps the icon for a spin and blocks the click.</Guarantee>
  <Guarantee story="DoesNotFireWhenDisabled">Disabled swallows the click, and neither disabled nor loading sinks on press.</Guarantee>
  <Guarantee story="RespondsToTheKeyboard">Space and Enter fire it, and the focus ring is the same 2 px lime as everything else in the system.</Guarantee>
  <Guarantee story="AsALink"><code>render</code> keeps the semantics of whatever element it becomes, including an anchor.</Guarantee>
  <Guarantee story="TheCursorSaysItIsPressable">The cursor is a pointer while it can be pressed and the default arrow when it cannot.</Guarantee>
</Guarantees>
