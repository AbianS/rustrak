## Summary

Currently, all management API endpoints (`/api/projects`, `/api/issues`, `/api/events`, `/api/tokens`, `/api/alerts`) require **session authentication** (web UI login with email+password). The `BearerAuth` extractor and token infrastructure are fully implemented but not wired into any route handler — making it impossible to use API tokens to query project/event data programmatically.

## Current State

- **Token infrastructure is complete:** `auth_tokens` table exists, `BearerAuth` extractor is functional, token CRUD works via the web UI
- **Zero endpoints use `BearerAuth`:** Every management endpoint uses `AuthenticatedUser` (session-based)
- **Documentation claims Bearer/Session auth exists** for management endpoints, but in reality only session auth is wired up

## Desired Behavior

Allow API tokens (created via the web UI at `/settings/tokens`) to authenticate management API requests via `Authorization: Bearer <token>` header, giving programmatic access to:

| Endpoint | Method | Description |
|---|---|---|
| `GET /api/projects` | GET | List projects |
| `GET /api/projects/{id}` | GET | Get project details |
| `GET /api/projects/{id}/issues` | GET | List issues (paginated) |
| `GET /api/projects/{id}/issues/{issue_id}` | GET | Get issue detail |
| `PATCH /api/projects/{id}/issues/{issue_id}` | PATCH | Resolve/mute issue |
| `GET /api/projects/{id}/issues/{issue_id}/events` | GET | List events (paginated) |
| `GET /api/projects/{id}/issues/{issue_id}/events/{event_id}` | GET | Get event full detail |

## Suggested Implementation

1. **Allow `BearerAuth` as an alternative to `AuthenticatedUser`** on management endpoints (either-or, not both required)
2. Create a composite extractor (e.g., `ApiAuth`) that tries `BearerAuth` first, falls back to `AuthenticatedUser`
3. Existing session auth behavior should remain unchanged

## Relevant Files

- `apps/server/src/auth/extractors.rs` — `BearerAuth` `FromRequest` impl (already working)
- `apps/server/src/auth/session.rs` — `AuthenticatedUser` extractor
- `apps/server/src/routes/projects.rs` — project CRUD
- `apps/server/src/routes/issues.rs` — issue management
- `apps/server/src/routes/events.rs` — event detail
- `apps/server/src/services/auth_token.rs` — `AuthTokenService`

## Priority / Impact

This would enable CI/CD integrations, monitoring dashboards, and automated alerting to consume Rustrak data without requiring a browser session — a core feature for any error tracking platform.
