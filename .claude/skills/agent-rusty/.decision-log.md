# Decision Log — agent-rusty

## Session — 2026-05-22 (initial build)

### Agent archetype: Memory Agent (not Stateless)

**Decision:** Memory Agent with configuration-style First Breath and evolvable capabilities.

**Rejected:** Stateless + sidecar YAML agent. Rejected because: (1) Rustrak's implementation state changes week-to-week — BOND.md tracking this across sessions removes the need to re-explain context each time; (2) anti-hallucination rules as CREED values (identity) is more robust than external instructions.

**Rejected:** Full calibration-style First Breath. Rejected because the relationship is domain-tool-oriented, not long-term creative companion. Configuration-style (warm but efficient) is the right fit.

### Agent format: new BMad stateless template — NOT legacy `.agent.yaml`

**Decision:** Uses new BMad agent-builder architecture: lean SKILL.md bootloader + sanctum folder + customize.toml.

**Rejected:** Legacy `.agent.yaml` format. Confirmed legacy — the current BMad installation has no `.agent.yaml` files anywhere. New format is more maintainable and supported.

### User-local config: `~/.rusty/`

**Decision:** Machine-specific state lives in `~/.rusty/` — never committed to repo. This includes cloned repos (`relay-repo/`, `sentry-data-schemas/`) and `config.yaml` (repo paths, last SHA).

**Why:** User's explicit requirement. Repos are large and machine-specific; credentials (if added later) must not be committed. User-local directories keep machine state out of the repo.

**Lint note:** The path-standards scanner flags all `~/.rusty/` references as "environment-specific" (34 HIGH findings). These are INTENTIONAL FALSE POSITIVES — by design, these are machine-local paths. The scanner does not know about this user-local directory pattern. Findings suppressed: all `absolute-path` category findings for `~/.rusty/`.

### Repos to clone

**Decision:** Two repos at initial build:
1. `getsentry/relay` — sparse checkout of protocol/schema crates + tests (~150MB)
2. `getsentry/sentry-data-schemas` — full clone (~5MB), contains canonical `relay/event.schema.json`

**Rejected for now:** `getsentry/sentry-javascript`, `getsentry/sentry-python`, `getsentry/ingest-load-tester`. Deferred — user can add via evolvable capabilities when needed.

### No PULSE (autonomous mode)

**Decision:** No autonomous mode. The Sentry expert is a demand-driven investigator — value comes from focused sessions, not background checks.

**Note:** `sentry-protocol-drift` skill already handles automated monitoring. The two are complementary: protocol-drift monitors, Rusty investigates.

### Language

**Decision:** `communication_language` from `_bmad/config.user.toml` (Spanish for this owner). All files, artifacts, CREED, BOND, capability prompts, session logs: English. Conversation with owner: in their language.

### Evolvable capabilities

**Decision:** Yes. `CAPABILITIES.md` has a "Learned" section. `references/capability-authoring.md` teaches Rusty how to create new capabilities collaboratively. Capabilities live in `capabilities/` folder in the sanctum.

### init-sanctum.py reads TOML config

**Decision:** Script reads `_bmad/config.toml` and `_bmad/config.user.toml` using `=` separator (TOML format), not the template's original `:` separator (YAML format). The project uses TOML config files — the original template's YAML parsing would not work.
